# Введение

По тактовой частоте современные процессоры вышли на плато, хотя число транзисторов по Муру ещё растёт. Лишние транзисторы идут в ядра, а не в GHz -> единственный путь ускорять программы — параллелизм.

В курсе: **1 CPU = 1 ядро**.

## Архитектуры

### 1. Общая память (shared memory)

Все процессоры видят **одно адресное пространство**. Обмен данными - обычные load/store. На практике это потоки одного процесса (pthreads, OpenMP).

- мало накладных расходов на обмен (память, не сеть)
- удобно для небольших SMP/NUMA-узлов
- большие SMP-машины дорогие
- плохо масштабируются (шины, когерентность кэшей, NUMA)
- тяжёлый теплоотвод

Программирование: OpenMP

### 2. Распределённая память (distributed memory)

У каждого узла **своя** память. Узлы — «мини-компьютеры», связанные сетью. Обмен — **явная передача сообщений**.

- дешевле, легче масштабировать (кластеры)
- нет общего кэша / общей шины
- сеть медленнее памяти -> критичен overhead коммуникаций
- сложнее писать; не любой алгоритм хорошо распараллеливается
- данные надо явно пересылать (нет общего адреса)

Программирование: MPI

Современный кластер почти всегда **гибрид**: узлы с общей памятью + сеть между узлами -> MPI между узлами, OpenMP внутри узла.

## MPI

**MPI** — Message Passing Interface — **спецификация** (не библиотека) стандарта для параллельных программ на передаче сообщений.

Реализации: Open MPI, MPICH, Intel MPI, MVAPICH, ...

Интерфейсы: **C и Fortran**. Официальный Cppbinding был в MPI-2, в MPI-3 его убрали. Для Cpp в курсе — **Boost.MPI** (обёртка над C API).

Стандарты обратно совместимы: MPI-1.0 (1994) ... MPI-4.1 (2023); MPI-5.0 в разработке.

**В этом курсе — MPI-1.1** (1995).

### Модель программирования

MPI даёт **виртуальный интерфейс** к любой машине с распределённой памятью — независимо от ОС и сети.

- **SPMD**: один и тот же бинарник на всех процессах, роли различаются по `rank`
- параллелизм **явный**: сам решаешь, кто кому что шлёт
- число процессов **статично**, задаётся при запуске (`mpirun -np N`)
- MPI-процесс = обычный процесс ОС (не поток)



### Процессы, группы, rank

- процессы состоят в **группах**
- **коммуникатор** = группа + контекст общения (чтобы сообщения разных "миров" не путались)
- `MPI_COMM_WORLD` — предопределённый коммуникатор: **все** процессы данного запуска
- внутри коммуникатора у процесса уникальный **rank** (task id)
- rank — это `int`, от `0` до `N-1` с шагом 1 (`N` = размер группы)
- типичный паттерн: `if (rank == 0) { /* мастер: ввод/вывод */ }`

Один процесс может входить в несколько коммуникаторов и иметь в них **разные** rank.

### Минимум API (есть в каждом MPI-программе)

Всё в `<mpi.h>`, все имена с префиксом `MPI_`.


| вызов           | смысл                              |
| --------------- | ---------------------------------- |
| `MPI_Init`      | подключить процесс к MPI-окружению |
| `MPI_Comm_size` | сколько процессов в коммуникаторе  |
| `MPI_Comm_rank` | мой номер в коммуникаторе          |
| `MPI_Finalize`  | выйти из MPI-окружения             |


`MPI_Init` / `MPI_Finalize` **не создают и не убивают** процессы: их порождает `mpirun`/`mpiexec` *до* `main`. Init только "связывает" уже запущенные процессы в коммуникатор, Finalize — завершает общение (после него MPI-вызовы нельзя).

- `MPI_Init` вызывается **ровно один раз**, и это **первый** MPI-вызов
- почти все MPI-функции - строго между `Init` и `Finalize`
- в C нет ссылок -> выходные аргументы (`rank`, `size`, ...) передаются **по указателю**
- каждая функция возвращает `int` - код ошибки; успех = `MPI_SUCCESS`
- по умолчанию обработчик ошибок - abort всей задачи; **в ДЗ коды всё равно проверять**
- `MPI_Init(&argc, &argv)` может вырезать из `argv` свои флаги (типа `--mca …`)

Сигнатуры:

```c
int MPI_Init(int *argc, char ***argv);
int MPI_Comm_size(MPI_Comm comm, int *size);
int MPI_Comm_rank(MPI_Comm comm, int *rank);
int MPI_Finalize(void);
```



### Hello world (C)

```c
#include <stdio.h>
#include <mpi.h>

int main(int argc, char *argv[])
{
    int numtasks, rank;
    int rc;

    rc = MPI_Init(&argc, &argv);
    if (rc != MPI_SUCCESS) {
        fprintf(stderr, "MPI_Init failed\n");
        return 1;
    }

    rc = MPI_Comm_size(MPI_COMM_WORLD, &numtasks);
    if (rc != MPI_SUCCESS) {
        MPI_Abort(MPI_COMM_WORLD, rc);
    }

    rc = MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    if (rc != MPI_SUCCESS) {
        MPI_Abort(MPI_COMM_WORLD, rc);
    }

    printf("Hello, world! I am %d of %d\n", rank, numtasks);

    MPI_Finalize();
    return 0;
}
```

`MPI_Abort(comm, errorcode)` аварийно завершает все процессы коммуникатора.

### Hello world (Boost.MPI)

`mpi::environment` в конструкторе зовёт `MPI_Init`, в деструкторе — `MPI_Finalize` (RAII). Для MPI-1.1 аргументы `argc`/`argv` обязательны. Нельзя создавать `environment` в глобальной области — UB.

```cpp
#include <boost/mpi.hpp>
#include <iostream>

namespace mpi = boost::mpi;

int main(int argc, char *argv[])
{
    mpi::environment env(argc, argv);   // MPI_Init
    mpi::communicator world;            // MPI_COMM_WORLD

    std::cout << "Hello, world! I am " << world.rank()
              << " of " << world.size() << std::endl;

    return 0;                           // ~env → MPI_Finalize
}
```

Boost.MPI кидает исключения вместо кодов ошибок (если не настроен иначе).

### Компиляция

`mpicc`, `mpiCC` / `mpicxx` / `mpic++` — обёртки над обычными компиляторами: сами подставляют `-I`, `-L`, `-lmpi`.

```bash
mpicc  -o hello hello.c
mpicxx -o hello hello.cpp          # Boost: ещё -lboost_mpi -lboost_serialization
```



### Запуск

MPI-окружение поднимает лаунчер, не сам бинарник. Без него обычно получается **1 процесс** (если вообще запустится).

Имена и флаги зависят от реализации и кластера: `mpirun`, `mpiexec`, иногда `srun`. На нескольких узлах лаунчер ходит по `ssh`/`rsh`.

```bash
mpirun -np 5 ./hello      # Open MPI / MPICH
mpiexec -n  5 ./hello     # то же по смыслу, переносимее
```

`-np` / `-n` — число процессов. Можно больше, чем ядер: процессы будут делить ядра (обычно медленнее, для отладки ок).

### Вывод на экран

- порядок строк **не гарантирован**: кто первый дошёл до `printf`, тот и напечатал
- MPI **не гарантирует**, что символы одной строки одного процесса не перемешаются с чужими (stdout без блокировки)
- практическое правило: отладочный вывод с `rank` в каждой строке; итоговый отчёт — только с rank 0
